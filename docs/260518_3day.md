## 2~3교시: 프로그래밍 패러다임, 자바 개요

- 절차지향 프로그래밍
    - 프로그램 실행 순서, 절차를 중요하게 여기며 함수 중심으로 처리하는 방식
    - 데이터 보다 함수가 중심
    - 특징
        - 컴퓨터의 처리 구조와 유사
        - 실행 속도가 빠름
        - 흐름을 파악하기 쉬움
        - 데이터와 함수가 분리되어 있음 → 데이터 구조가 변경되면 관련 함수도 모두 변경해야 하는 번거로움
    - 언어: C, Pascal, Fortran, COBOL
- 객체지향 프로그래밍 (OOP)
    - 데이터와 관련 함수를 객체라는 하나의 단위로 묶어 관리하는 방식
    - 실제 세계의 사물을 모델링하여 설계
    - 특징
        - 코드 재사용성이 높고 유지보수가 쉬움
        - 설계에 시간이 많이 소요됨
        - 절차지향에 비해 성능적으로 트레이드 오프가 존재함
    - 언어: Java, C++, Python, C#
- 자바의 탄생
    - 1991, 썬 마이크로시스템즈의 ‘그린 팀’이라 불리는 엔지니어들이 모여 시작
    - 가전제품들이 서로 연결되어 동작하는 ‘지능형 가전 네트워크’ 개발을 목표로 각 가전 제품의 하드웨어를 제어하는 플랫폼 구축
        - 가전제품마다 CPU 사양이 제각각
        - 당시 주력 언어인 C++은 플랫폼마다 코드를 새로짜야하는 번거로움
        - **플랫폼 독립적이고 네트워크 통신에 최적화된 새로운 언어의 필요성**
    - ‘그린 팀’ 프로젝트는 실패했지만, 당시에 보급되기 시작한 인터넷 환경에서 강점을 보이는 Java의 애플릿이 주목을 받게 됨
    - 애플릿(Applet)
        - 웹 브라우저에 포함된 클라이언트 측에서 실행되는 소규모 자바 프로그램
        - HTML만으로 부족했던 동적인 기능을 구현하기 위해 사용되었던 기술
        - 현재는 JavaScript가 그 자리를 차지
- 자바의 특징
    - WORA(Write Once, Run Anywhere)
    - 운영체제 독립성: JVM을 통해 어떤 플랫폼이든 동일하게 실행
    - 순수 객체지향: 설계부터 객체지향 원칙을 따름
    - 자동 메모리 관리(GC): 개발자가 직접 메모리를 관리할 필요 없이 가비지 컬렉터가 관리
    - 멀티스레드 지원: 언어 차원에서 강력한 멀티스레드 API를 제공
- JVM 개요
    - 자바는 OS가 직접 실행하지 않고 JVM이라는 가상 머신이 중간에서 실행
    - 코드 실행 순서: java 파일 작성 → 컴파일러(javac)가 바이트코드(.class)로 변환 → JVM의 클래스 로더가 .class를 메모리로 적재 → 실행 엔진이 한 줄씩 읽으며 기계어로 변환하여 실행
- JVM의 요소
    - 인터프리터: 바이트코드를 한 줄씩 읽어서 네이티브 코드로 해석, 실행
    - JIT(Just-In-Time) 컴파일러: ‘핫 스팟’이라는 자주 호출되는 코드 영역을 감지하면 해당 바이트코드 전체를 기계어로 컴파일하여 캐시에 저장, 이후 인터프리팅 없이 직접 실행
    - 가비지 컬렉터: 런타임 데이터 영역의 Heap 메모리를 관리하며, 더 이상 참조되지 않는 객체들을 식별하고 제거
- JRE (Java Rumtime Environment)
    - 자바 프로그램이 실행되기 위한 환경
    - JVM과 핵심 라이브러리 포함
- JDK (Java Development Kit)
    - JRE, 컴파일러, 디버거 등 자바 개발에 필요한 도구 모음
    - 구성 요소
        - javac: 컴파일러
        - java: 인터프리터, JVM을 구동
        - jar: 여러 클래스 파일과 리소스를 묶어 관리하는 압축 도구
        - jdb: 디버거
- LTS와 기능 릴리스(Feature Release)의 차이
    - LTS: 일반적인 버전보다 훨씬 더 긴 기간(5년 이상) 동안 보안 패치와 버그 수정을 지원, 실무 환경에서는 주로 이 버전을 채택
    - 기능 릴리즈: 6개월 주기로 출시되는 일반 버전, 다음 버전이 나오면 곧바로 지원 종료, 새로운 문법과 기능을 실험해 보기 위한 목적
- JDK 버전 특징 요약
    - Java 8: 람다식, 스트림 API, 현대 자바의 기반이 된 버전
    - Java 11: HTTP 클라이언트 API, String 유틸리트 메소드 확장, 모듈 시스템 안정화
    - Java 17: 텍스트 블록, Record 클래스 도입, SpringBoot 3.x의 최소 요구 버전
    - Java 21: 가상 스레드 정식 도입으로 동시성 처리 성능 대폭 향상
    - Java 25: 가장 최근 출시된 LTS, 패턴 매칭 고도화 및 데이터 지향 프로그래밍 등 성능 최적화
- 주요 JDK 배포판
    - OpenJDK
        - 자바의 공식 레퍼런스 구현체, 오픈소스
        - 대부분의 다른 배포판들이 해당 배포판을 기반으로 만듬
        - 표준 배포판
    - Oracle JDK
        - 오라클에서 제공하는 상업용 버전
        - 개인 및 개발 용도는 무료, 기업은 라이선스 비용 발생
        - 안정적인 기술 지원
    - Amazon Corretto
        - 아마존에서 제공, 성능 최적화와 보안 패치가 잘 관리됨
        - AWS 환경에 최적화
    - Azul Zulu
        - 임베디드나 특정 클라우드 환경에 최적화된 버전
        - 호환성이 높음
    - Eclipse Temurin
        - 커뮤니티 주도로 운용, 특정 기업에 종속되지 않고 중립적인 배포 지향
- IDE (Integrated Development Environment, 통합 개발 환경)
    - 프로그래밍에 필요한 코드 편집기, 컴파일러, 디버거 등을 하나로 모아놓은 소프트웨어
    - IntelliJ IDEA, Eclipse, Visual Studio Code

## 4~5교시: 데이터 타입

- 기본 데이터 타입: 프로그래밍에서 더 이상 쪼갤 수 없는 가장 기본 단위의 데이터 타입
- 정수형
    - byte (1 byte): -128 ~ 127
    - short (2 byte): -32768 ~ 32767
    - int (4 byte): -2147483648 ~ 2147483647, 자바 정수 기본 타입
    - long (8 byte): -2^63 ~ 2^63 - 1, int 범위를 넘어서 값을 할당시 끝에 L을 붙여야한다.
- 실수형
    - float (4 byte): 유효 숫자 7자리 정밀도, 할당시 끝에 F(f)를 붙여야한다.
    - double (8 byte): 유효 숫자 15자리 정밀도, 자바 실수 기본 타입
- 논리형, 문자형
    - boolean (1 byte): true, false
    - char (2 byte): 홑따옴표로 문자 하나만 저장, 내부적으로 유니코드(UTF-16) 숫자로 저장
- 참조 데이터 타입
    - 기본 데이터 타입을 제외한 모든 데이터 타입 (배열, 클래스 등)
    - 객체가 메모리 상에 실제 올라가 있는 위치 주소(Reference)를 가리키는 방식

## 6교시: 변수

- 변수
    - 데이터를 담는 그릇
    - 변수에 값을 저장한 다음 그 값이 필요할 때 변수를 통해서 값을 사용
    - 값을 수정할 수 있음
    - 고유한 이름을 가짐
- 변수 선언
    - 데이터를 사용하기 전에 특징에 맞는 데이터 타입을 미리 지정 (예: int x)
- 변수에 값 할당
    - 대입연산자(=)를 이용하여 값을 할당 (예: x = 25)
    - 변수 선언과 동시에 값 할당도 가능 (예: int x = 25)
