## 2~4교시: 캡슐화, Getter와 Setter

- Getter와 Setter 작성 규칙 (네이밍 관례)
  - 일반적인 필드 네이밍 규칙
    - Getter: get + 필드명 (예: String name → getName)
    - Setter: set + 필드명 (예: String name → setName)
  - 논리형 필드
    - 논리형 필드의 경우 Getter는 get을 사용하는 대신 is로 시작하는 것이 관례
    - 예: boolean isSoldOut → isSoldOut

## 5교시: static

- static
  - static 필드나 메소드는 인스턴스 생성을 하지 않아도 클래스명으로 바로 접근 가능
  - 모든 인스턴스가 공유하는 메모리(메소드 영역)에 저장됨
- static 메소드의 제한 사항
  - static 메소드는 객체 생성 전 클래스 로딩 시점에 메모리에 올라가므로, 메모리에 존재 여부가 불확실한 인스턴스 필드나 인스턴스 메소드에 직접 접근할 수 없음.
  - static 메소드 내부에서는 오직 static 필드(클래스 변수)나 static 메소드만 직접 호출 가능
  - this 키워드는 static 메소드 내부에서 사용할 수 없음.
    - this는 객체(인스턴스)가 존재한 후에 사용할 수 있기 때문에
  - 대표적인 static 메소드인 main 메소드 내부에서 동일 클래스의 다른 일반 메소드를 직접 호출하려면 컴파일 에러가 발생.
    - 이를 호출하려면 대상 메소드가 static이거나, main 메소드 내에서 자기 자신의 객체를 new로 생성하여 접근해야 함.

## 6교시: 지역별 변수 종류와 비교

- 변수의 종류와 비교 (지역 변수, 인스턴스 변수, 클래스 변수)

| 구분 | 지역 변수 (Local Variable) | 인스턴스 변수 (Instance Variable / 필드) | 클래스 변수 (Class Variable / 정적 필드) |
| :--- | :--- | :--- | :--- |
| 선언 위치 | 메서드, 생성자, 블록 내부 | 클래스 블록 내부 (static 없음) | 클래스 블록 내부 (static 있음) |
| 저장 영역 | 스택 (Stack) 영역 | 힙 (Heap) 영역 | 메서드 (Method / Static) 영역 |
| 초기화 방식 | 자동 초기화 안 됨 (사용 전 초기화 필수) | 기본값으로 자동 초기화 | 기본값으로 자동 초기화 |
| 생성 시점 | 변수 선언문이 실행될 때 | 객체(인스턴스)가 생성될 때 | 클래스가 메모리에 로드될 때 |
| 소멸 시점 | 선언된 블록이 종료될 때 | 객체가 GC에 의해 소멸할 때 | 프로그램이 종료될 때 |

- 메모리 저장 영역과 생명 주기의 차이
  - 지역 변수
    - 메소드가 호출될 때 JVM 스택 영역의 스택 프레임 내부에 생성
    - 메소드 실행이 완료되면 해당 스택 프레임이 제거되면서 지역 변수도 즉시 소멸
  - 인스턴스 변수(필드)
    - 객체가 new 연산자로 생성될 때 JVM 힙 영역에 생성
    - 객체가 더 이상 참조되지 않아 GC에 의해 수거되어 소멸할 때까지 힙 메모리에 유지
  - 클래스 변수(정적 필드)
    - 프로그램 실행 시 해당 클래스가 메모리에 로드될 때 JVM 메소드 영역에 단 한 번 생성
    - 프로그램 전체에서 공유
    - 프로그램이 종료될 때까지 메모리에 유지
