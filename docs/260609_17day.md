## 2교시: 추상 클래스

- 추상 클래스
    - 실체 클래스들의 공통적인 특성(필드, 메소드)을 추출하여 선언한 미완성 설계도
    - 미완성 클래스이므로 단독으로 객체를 생성할 수 없음
    - 클래스 선언부에 abstract 키워드를 붙여 정의
    - 추상 클래스의 특징
        - 직접적인 객체 생성 불가: 설계도 자체가 미완성이므로 new 연산자를 사용하여 단독으로 인스턴스를 생성할 수 없음
        - 생성자 보유: 직접 객체를 생성할 수 없지만, 자식 객체가 생성될 때 부모 생성자인 super()를 호출해야 하므로 생성자가 반드시 존재하고 호출됨
        - 일반 멤버 포함 가능: 추상 메소드 외에도 일반적인 필드(멤버 변수)와 완성된 바디를 가진 일반 메소드를 자유롭게 가질 수 있음
- 추상 메소드
    - 선언부만 있고 구현부(중괄호 블록)가 없는 메소드
    - abstract 키워드를 사용하여 선언
    - 자식 클래스에게 특정 동작의 구현을 강력하게 강제하기 위해 사용
    - 추상 클래스를 상속받은 자식 클래스는 부모의 모든 추상 메소드를 반드시 오버라이딩하여 구체적으로 구현, 그렇지 않을 경우 자식 클래스 역시 추상 클래스로 선언해야 함.
- 실체 클래스가 아닌 추상 클래스로 선언하는 이유
    - 부모 클래스의 단독 객체 생성 차단
        - Animal이나 Shape처럼 그 자체로 실체가 없는 추상적인 개념의 클래스가 단독 객체로 만들어지는 실수를 방지
    - 자식 클래스의 특정 메소드 구현 강제
        - 일반 부모 클래스의 메소드는 자식 클래스에서 오버라이딩을 생략하더라도 문제가 없어 실수할 여지가 있음. (컴파일, 런타임에서 에러가 없음)
        - 추상 메소드는 상속받는 자식 클래스에서 강제적으로 재정의하도록 컴파일 시점에서 검증

## 3~5교시: 인터페이스

- 인터페이스
    - 객체의 사용 설명서이자 극단적인 추상화 설계도
    - 구현부 없이 오직 객체가 수행해야 할 동작의 규격(스펙)만을 정의해 둔 클래스
    - 클래스들이 가져야 할 기능의 공통 표준 규격을 마련하기 위해 사용
- 인터페이스의 문법적 특징
    - 클래스 선언 시 class 대신 interface 키워드를 사용하여 선언
    - 인터페이스 내의 멤버 변수는 컴파일 시 자동으로 public static final 상수로 취급
        - 따라서 선언과 동시에 초기화해야 함
    - 인터페이스 내부의 메소드는 기본적으로 구현부(중괄호 블록)가 없는 추상 메소드로 선언
        - 자동으로 public abstract 제어자가 지정됨
    - 다중 구현 지원
        - 자바는 클래스 상속의 단일 상속 제약을 극복하기 위해 인터페이스를 통한 다중 구현을 완벽히 지원함
        - 하나의 클래스가 여러 인터페이스를 implements 키워드 뒤에 콤마(,)로 나열하여 동시에 구현할 수 있음
    - 추상 클래스와 마찬가지로 단독으로 인스턴스화 할 수 없음
- 인터페이스 구현과 규격 일치
    - 구현 클래스는 인터페이스에 정의된 모든 추상 메소드를 반드시 오버라이딩하여 body를 완성해야 함
    - 인터페이스의 메소드는 묵시적으로 public이므로, 오버라이딩할 때 자식 메소드의 접근 제어자는 반드시 public이어야 함
- 추상 클래스 vs 인터페이스
    - 추상 클래스 (Is-A):
        - 부모와 자식 간의 밀접한 혈연 관계
        - 상태(필드)와 일반 행위를 상속하여 공유하는 목적
    - 인터페이스 (Can-Do)
        - 혈연과 상관없이 공통적인 동작이나 특정 기능을 수행할 수 있는 능력(동작 규격)을 여러 클래스에 부여하는 목적
- 인터페이스의 구현 메소드 (default, static, private)
    - 자바 버전이 올라감에 따라 인터페이스의 활용도를 높이고 하위 호환성을 유지하기 위해, body(구현부)를 가질 수 있는 세 종류의 구현 메소드가 도입됨
- default 메소드
    - 기존 인터페이스에 새로운 메소드를 추가할 때, 이미 해당 인터페이스를 구현하고 있는 기존 클래스들의 수정 없이 공통적인 기본 기능을 제공하기 위해 도입됨
    - 접근 제어자의 default와는 완전 다른 개념
    - 오버라이딩은 선택적이며, 선언부에 default 키워드를 명시해야 함
    - 접근 제어자는 무조건 public, 생략시 자동으로 public으로 취급
- static 메소드
    - 객체 생성 없이 인터페이스명으로 직접 호출할 수 있는 정적 유틸리티 메소드
    - 접근 제어자를 생략하는 경우 자동으로 public static으로 취큽
    - 인터페이스 외부에서 직접 호출 가능
- private 메소드
    - 인터페이스 내부의 defalut 또는 static 메소드 내에서만 호출 가능한 비공개 보조 메소드
    - 구현 메소드 간의 공통 코드를 분리, 코드 중복을 방지함
    - 명시적으로 private 접근 제어자를 선언, defalut 키워드를 붙이지 않음

## 6교시: 자바 API 문서, String 클래스

- 자바 API 문서
    - 자바가 표준으로 설계하여 탑재해 둔 수천 개의 클래스, 인터페이스, 메소드들의 상세 명세서
    - 오라클 공식 자바 표준 문서 저장소: https://docs.oracle.com/en/java/javase/
        - JDK 버전을 선택한 후 API Documentation 확인
        - API 문서가 매우 방대하므로 검색 기능을 주로 활용
    - 통합 개발 환경(IDE) 내에서의 API 툴팁 활용
        - IntelliJ에서 웹 브라우저를 직접 열지 않고도, 소스코드 내 클래스명이나 메소드명 위에 마우스를 올리면 공식 자바 API 문서 설명이 팝업으로 표시
        - 단축키: Ctrl + Q (Windows) 또는 F1 (Mac) 키를 누르면, API 주석 설명문을 새로운 탭으로 확인 가능
- 자바 주요 패키지 개요
    - java.lang
        - 자바 프로그래밍의 가장 기본적인 클래스들을 담고 있는 패키지
        - 이 패키지의 클래스들은 import 구문 없이도 자동으로 사용가능
        - System, String, Object, Math 등
    - java.util
        - 자료구조, 날짜 처리, 난수 생성 등 프로그래밍의 다양한 유틸리티 도구를 제공하는 패키지
        - 사용 시 명시적인 import 필요
        - Scanner, Random, Calender, List 등
- String 클래스의 내부 메커니즘과 불변성(Immutability)
    - String 객체는 한 번 생성되면 메모리 상에서 내부 값을 변경할 수 없는 불변 객체임
    - 문자열 상수 풀 (String Constant Pool)
        - 메모리 효율성과 안정성을 위해 힙 메모리 내부에 특수한 공유 메모리를 구성
        - 리터럴 선언 시 상수 풀에서 동일 문자열 확인 후 참조
        - 따라서, 내용 비교를 위해선 equals 사용 권장
    - 문자열 결합 연산의 부작용
        - (+) 연산 시 새로운 문자열 객체가 생성되어 임시 객체가 힙 영역에 쌓임
        - 루프 내 반복 연산 시 가비지 컬렉터 성능 저하 초래

## 의문점

- 저번 시간에 문자열 상수 풀에 대한 설명으로는 메소드 영역에 저장된다고 했는데, 지금보니 힙에 저장된다고 적혀있다. 어떻게 된거지?

  → Java 8 버전 이전까지는 메소드 영역의 Runtime Constant Pool에 저장되고 있었지만, 이후 메모리 부족으로 인한 OOM 발생으로 힙 영역에 String Constant Pool을 만들어 관리하게 되었다.
