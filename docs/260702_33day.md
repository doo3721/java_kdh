## 2~3교시: 입출력, Input/OutputStream

- 입출력(I/O)
    - 입력(Input)과 출력(Output)의 약어
    - 컴퓨터 프로그램이 외부 환경(콘솔 창, 파일, 네트워크 등)과 데이터를 주고받는 모든 동작을 의미함
    - 데이터 근원지(Source)와 목적지(Destination)
        - 데이터 근원지(Source)
            - 프로그램으로 데이터가 흘러 들어오는 출발지점
            - 키보드, 파일, 네트워드 등
        - 데이터 목적지(Destination)
            - 프로그램에서 가공된 데이터가 최종적으로 도착하는 지점
            - 콘솔 창, 파일, 네트워크 등
    - 스트림의 정의
        - 데이터 근원지와 목적지 사이에 데이터를 순서대로 주고받기 위해 형성되는 단방향 데이터 흐름
        - 입력 장치로부터 데이터를 읽어 들이는 입력 스트림과 데이터를 외부로 송출하는 출력 스트림이 완전 분리되어 독립적으로 동작함
    - 자바 I/O 다형성과 상속 관계
        - 데이터 근원지나 목적지가 물리적으로 다를지라도, 자바 프로그램 내부에서는 다형성(polymorphism)을 활용해 공통된 코드로 다룰 수 있도록 java.io 패키지의 입출력 클래스들이 체계적인 상속 관계를 형성하고 있음
        - 모든 바이트 단위의 입력 클래스는 최상위 추상 클래스인 InputStream을, 출력 클래스는 OutputStream을 상속함
        - 모든 문자 단위의 입력 클래스는 최상위 추상 클래스인 Reader를, 출력 클래스는 Writer를 상속함
        - 개발자는 실제 데이터 소스가 파일(FileInputStream)이든 콘솔 창이든 상관없이, 상위 추상 클래스 타입으로 통일하여 read()나 write() 메소드를 호출하는 단일화된 공통 코드를 작성할 수 있음
- I/O 클래스의 분류 체계
    - 데이터 이동 단위에 따른 분류
        - 바이트 단위 입출력
            - 1byte 단위 데이터 처리 수행
            - 그림, 동영상, 압축 파일 등 모든 형태 바이너리 데이터 대상 적용
            - 최상위 클래스는 InputStream/OutputStream
        - 문자 단위 입출력
            - 2byte(또는 유니코드 가변 단위) 크기 텍스트 데이터를 문자 단위로 처리
            - 최상위 클래스는 Reader/Writer

      | ***InputStream*** |  | **기능** | ***OutputStream*** |  |
              | --- | --- | --- | --- | --- |
      | **1차 스트림** | **2차 스트림** |  | **2차 스트림** | **1차 스트림** |
      | FileInputStream | - | 파일 대상 입출력 수행 | - | FileOutputStream |
      | - | BufferedInputStream | 버퍼 기능 추가를 통한 성능 향상 | BufferedOutputStream | - |
      | - | ObjectInputStream | 객체 단위 입출력 수행 | ObjectOutputStream | - |
      | - | - | 다양한 타입의 데이터 포맷 출력 편의 제공 (System.out) | PrintStream | - |
    - 연결 방식 기준에 따른 분류
        - 1차 스트림 (기본 스트림 또는 노드 스트림)
            - 실제 입출력 장치(파일, 메모리 등)와 직접 연결하여 입출력 수정
        - 2차 스트림 (보조 스트림 또는 프로세싱 스트림)
            - 1차 스트림 또는 다른 2차 스트림과 연결되어 데이터 가공, 버퍼링 등 추가 기능 수행

      | ***Reader*** |  | **기능** | ***Writer*** |  |
              | --- | --- | --- | --- | --- |
      | **1차 스트림** | **2차 스트림** |  | **2차 스트림** | **1차 스트림** |
      | FileReader | - | 파일 대상 입출력 수행 | - | FileWriter |
      | - | BufferedReader | 버퍼 기능 추가를 통한 성능 향상 | BufferedWriter | - |
      | - | InputStreamReader | 바이트 단위 입출력과 문자 단위 입출력 간 전환 가교 역할 | OutputStreamWriter | - |
      | - | - | 다양한 포맷팅 출력 기능 오버로딩 제공 (Servlet 출력 객체) | PrintWriter | - |
- InputStream과 OutputStream의 주요 메소드
    - InputStream 주요 메소드
        - `int read()`: 입력 스트림으로부터 1바이트 데이터를 읽어 정수형(0~255)으로 반환함. 읽을 데이터가 없을 시 -1을 반환함
        - `int read(byte[] b)`: 바이트 배열 b 크기만큼 데이터를 읽어 배열에 저장함. 읽은 바이트 수를 반환하며 끝 도달 시 -1을 반환함
        - `int read(byte[] b, int offset, int length)`: 바이트 배열 b의 offset 위치부터 length 크기만큼 데이터를 읽어 저장하고 읽은 바이트 수를 반환함. 끝 도달 시 -1을 반환함
        - `void close()`: 스트림 자원을 반환하고 입력 스트림 연결을 끊음
    - OutputStream 주요 메소드
        - `void write(int b)`: 출력 스트림에 1바이트 데이터를 기록함
        - `void write(byte[] b)`: 바이트 배열 b의 모든 데이터를 출력 스트림에 기록함
        - `void write(byte[] b, int offset, int length)`: 바이트 배열 b의 offset 위치부터 length 크기만큼 데이터를 읽어 출력 스트림에 기록함
        - `void flush()`: 출력 버퍼에 남아있는 데이터를 강제로 전송함
        - `void close()`: 시스템 자원을 반환하고 출력 스트림 연결을 끊음
    - Reader와 Writer의 주요 메소드
        - Reader와 Writer는 InputStream, OutputStream과 동일하며 데이터 단위만 byte에서 char로 달라짐
        - 추가로 문자 단위 출력 편의를 위해 문자열을 곧바로 전송할 수 있는 `void write(String str)` 메서드가 Writer 클래스에 별도로 제공됨

## 4교시: 파일 입출력 클래스

- 파일 입출력 클래스
    - File
        - 시스템의 파일이나 디렉토리를 관리하는 클래스
        - 파일의 생성, 삭제, 존재 여부 확인 등 파일 자체의 정보와 물리적 속성을 제어하는 기능을 제공
        - 생성자
            - `File(String pathname)`: 지정된 경로 이름의 문자열을 기반으로 File 객체를 생성
            - `File(String parent, String child)`: 부모 디렉터리 경로와 자식 파일 이름을 조합하여 File 객체를 생성
        - 메소드
            - `boolean exists()`: 해당 경로에 파일 또는 디렉터리가 실제로 존재하는지 여부를 판단
            - `boolean createNewFile()`: 해당 경로에 새로운 물리 파일을 생성
            - `boolean delete()`: 해당 파일 또는 디렉터리를 물리적으로 삭제
            - `boolean isFile()`: 해당 객체가 일반 파일인지 여부를 판단
            - `boolean isDirectory()`: 해당 객체가 디렉터리인지 여부를 판단
            - `String getName()`: 파일 또는 디렉터리의 이름을 반환
            - `String getAbsolutePath()`: 해당 파일의 절대 경로를 반환
            - `long length()`: 파일의 크기를 반환
    - FileInputStream
        - 파일로부터 1바이트씩 데이터를 읽어 들이는 입력 클래스
        - 생성자
            - `FileInputStream(String name)`: 지정된 파일 경로 이름을 기준으로 `입력 객체`를 생성
            - `FileInputStream(File file)`: 지정된 File 객체를 기준으로 `입력 객체`를 생성
        - 메소드
            - `int read()`: 파일로부터 1바이트 데이터를 읽어 정수형(0~255)으로 반환. 파일 끝에 도달하면 -1을 반환함
            - `int read(byte[] b)`: 파일로부터 배열 b의 크기만큼 데이터를 읽어 배열에 저장. 읽은 바이트 수를 반환하며 파일 끝 도달 시 -1을 반환함
            - `int read(byte[] b, int offset, int length)`: 파일로부터 length 크기만큼 데이터를 읽어 배열 b의 offset 위치부터 저장. 읽은 바이트 수를 반환하며 파일 끝 도달 시 -1을 반환함
            - `void close()`: 파일 입력 연결을 닫고 시스템 자원을 반환함
    - FileOutputStream
        - 대상 파일에 1바이트씩 데이터를 기록하는 출력 클래스
        - 생성자
            - `FileOutputStream(String name)`
                - 지정된 파일 경로 이름을 기준으로 `파일 출력 객체`를 생성
                - 파일이 존재하지 않으면 새로 생성하고, 기존 파일이 존재하면 덮어씀
            - `FileOutputStream(String name, boolean append)`
                - 지정된 파일 경로 이름을 기준으로 `파일 출력 객체`를 생성
                - 파일이 존재하지 않으면 새로 생성하고, 기존 파일이 존재하면 append 값에 따라서 덮어쓸지 이어쓸지 결정됨 (true면 기존 내용 뒤에 이어서 기록, 기본값은 false)
            - `FileOutputStream(File file)`
                - 지정된 File 객체를 기준으로 `파일 출력 객체`를 생성
                - 파일이 존재하지 않으면 새로 생성하고, 기존 파일이 존재하면 덮어씀
            - `FileOutputStream(File file, boolean append)`
                - 지정된 File 객체를 기준으로 `파일 출력 객체`를 생성
                - 기존 파일이 존재하면 append 값에 따라서 덮어쓸지 이어쓸지 결정됨 (true면 기존 내용 뒤에 이어서 기록, 기본값은 false)
        - 메소드
            - `void write(int b)`: 1바이트 데이터를 파일에 기록함
            - `void write(byte[] b)`: 바이트 배열 b의 모든 데이터를 파일에 기록함
            - `void write(byte[] b, int offset, int length)`: 바이트 배열 b의 offset 위치부터 length 크기만큼의 데이터를 파일에 기록함
            - `void flush()`: 출력 버퍼에 잔류하는 데이터를 물리 파일에 즉시 강제 전송함
            - `void close()`: 파일 출력 연결을 닫고 시스템 자원을 반환함
    - 파일 입출력의 예외 처리와 자원 해제
        - 파일 입출력 API는 파일이 없거나 디스크 접근에 실패하는 상황 등에 대비하여 예외 처리가 강제되는 Checked Exception 계열로 설계되어 있음
        - 외부 시스템 자원을 점유하므로 작업 완료 후 안전하게 닫아주기 위해 try-with-resources 구문 사용을 권장

## 5교시: 표준 입출력 장치, 입출력 예외와 자원 누수 대처

- 표준 입출력 장치
    - System.in
        - 표준 입력 스트림
        - 키보드로부터 데이터를 입력받기 위해 사용하는 InputStream 타입의 객체
        - JVM 구동 시 자동으로 생성됨
    - System.out
        - 표준 출력 스트림
        - 콘솔 창(화면)으로 데이터를 출력하기 위해 사용하는 PrintStream 타입의 객체
        - 주로 print(), println() 메소드를 통해 텍스트를 출력
    - System.err
        - 표준 에러 출력 스트림
        - System.out과 동일하게 콘솔 창에 출력
        - 주로 오류 메시지를 구분하여 출력하기 위한 용도로 사용하는 PrintStream 타입의 객체
- 입출력 예외와 자원 누수 대처
    - 파일 접근 실패 예외 (FileNotFoundException)
        - 원인
            - 지정한 경로에 대상 파일이 실제 존재하지 않을 경우
            - 읽기 전용 파일 쓰기를 시도할 경우
            - 디렉토리 경로를 파일명으로 지정하여 접근을 시도할 경우
        - 대처 요령
            - 파일 경로의 알파벳 대소문자 확인 및 실제 물리적인 파일의 존재 위치를 점검
            - 프로그램 코드 내에서 File 객체의 exist() 메소드를 사용하여 파일 존재 여부를 확인 후 사용
    - 스트림 미폐쇄로 인한 자원 누수
        - 원인
            - 스트림은 자바 내부 메모리가 아니라 운영체제로부터 권한을 얻어 개설하는 외부 데이터 연결 상태
            - 컴퓨터 전체에서 한 번에 열 수 있는 스트림의 개수가 한정되어 있음
            - 사용을 마친후 닫아서 반납하지 않으면 사용 가능한 스트림이 고갈
            - 새로운 파일이나 네트워크 연결을 열지 못하는 시스템 마비 현상 발생
        - 대처 요령
            - 다 사용한 스트림을 반납하기 위해 잊지말고 close() 호출
            - try-with-resources 문법을 사용해서 블록이 끝날 때 사용한 스트림 자원을 자동으로 안전하게 반납하도록 구성
    - 출력 데이터의 실시간 미반영과 버퍼 비우기
        - 원인
            - 자바 출력 스트림은 효율을 위해 메모리 버퍼를 거치는 특성이 있음
            - 버퍼에 데이터가 갇힌 상태에서는 실제 목적지로 데이터가 실시간 전송 되지 않는 지연 현상이 발생
        - 대처 요령
            - 출력 스트림을 닫는 close() 메소드는 내부적으로 버퍼를 비워내는 flush() 를 자동으로 함께 호출하므로 스트림 종료 시에는 데이터 누락이 발생하지 않음
            - 다만, 스트림 연결을 닫지 않고 계속 열어둔 상태로 실시간 즉시 전송해야 하는 상황(예: 네트워크 채팅 통신, 실시간 콘솔 데이터 모니터링 등)에서는 쓰기 작업 직후 반드시 명시적으로 flush() 를 호출하여 버퍼에 데이터가 다 차지 않았더라도 즉각 전송하도록 해야함

## 6교시: 네트워크, TCP 소켓 통신

- 네트워크 기초
    - IP 주소와 포트 번호
        - IP: 네트워크 환경에서 고유한 컴퓨터 위치 식별용 주소
        - Port: 컴퓨터 내부의 어떤 프로세스가 데이터 패킷을 수령해야 하는지 정확한 어플리케이션 목적지를 결정하는 고유 식별 번호
        - 포트의 3가지 분류 체계
            - 잘 알려진 포트 (Well-Known Ports, 0~1023): 주요 통신 규약용으로 국제인터넷주소관리기구(IANA)에 의해 사전 예약된 포트군 (OS 수준의 관리 권한이 필요함)
            - 등록된 포트 (Registered Ports, 1024~49151): 특정 기업의 솔루션이나 미들웨어 서비스 프로세스들이 사전 등록하여 활용하는 포트군 (예: 자바 톰캣 서버)
            - 동적/사설 포트 (Dynamic/Private Ports, 49152~65535): 클라이언트가 서버에 임시 접속할 때 운영체제가 즉석에서 무작위로 배정해 주는 발신용 임시 포트군
        - 실무적으로 자주 쓰이는 주요 표준 포트 번호
            - 22: SSH (보안 쉘 원격 제어 및 터미널 접속)
            - 25: SMTP (메일 전송 규약)
            - 80: HTTP (기본 웹 통신 프로토콜)
            - 443: HTTPS (보안 암호화 웹 통신 프로토콜)
            - 3306: MySQL / MariaDB (관계형 데이터베이스 기본 포트)
            - 8080: WAS / Tomcat (자바 웹 애플리케이션 서버 기본 테스트 포트)
    - 프로토콜 (Protocal)
        - 컴퓨터나 네트워크 장비들이 데이터를 올바르게 주고받기 위해 정의한 공통의 통신 규약
        - 전송하려는 데이터 패킷의 헤더 구성과 작성 서식이 해당 프로토콜(웹은 HTTP, 메일은 SMTP 등)의 엄격한 형식 규칙에 완벽히 들어맞아야만 전송이 이루어짐
    - 주요 프로토콜의 종류와 특징
        - TCP
            - 연결 지향성 프로토콜: 데이터를 주고받기 전에 송수신 컴퓨터 간의 논리적인 가상 연결 통로를 먼저 개설함 (3-Way Handshake 과정을 거침)
            - 높은 신뢰성: 패킷의 전송 순서를 보장하고 데이터 유실 발생 시 자동으로 재전송을 요청하는 흐름 제어 및 오류 복구 메커니즘이 내장됨
            - 적용 분야: 웹 브라우징(HTTP), 이메일, 파일 전송(FTP) 등 데이터 정합성이 절대적으로 중요한 분야에 사용
            - 속도는 UDP에 비해 다소 느림
        - UDP
            - 비연결성 프로토콜: 연결을 수립하는 과정 없이 데이터를 독립적인 패킷(Datagram) 단위로 목적지를 향해 일방적으로 던지는 방식
            - 빠른 속도와 경량성: 흐름 제어나 수신 확인 절차가 없기 때문에 지연 시간이 거의 없고 속도가 극도로 빠름
            - 적용 분야: 동영상 실시간 스트리밍, 온라인 게임, IP 전화(VolP) 등 일부 데이터가 유실되더라도 실시간 전송 속도가 중요한 서비스에 적합함
        - HTTP (HyperText Transfer Protocal)
            - 웹 환경에서 클라이언트(브라우저)와 서버가 텍스트, 이미지, HTML 문서 등을 주고받기 위해 사용하는 프로토콜
            - TCP 프로토콜 기반으로 동작
            - 요청(Request)과 응답(Response) 구조: 클라이언트가 서버에 데이터를 요청하면 서버가 이에 대응하는 결과를 돌려주고 연결을 끊는 무상태성(Stateless)을 기본 특징으로 함
- TCP 소켓 통신
    - 소켓 (Socket)
        - 운영체제 수준에서 네트워크를 통해 멀리 떨어진 두 컴퓨터의 프로세스 간 양방향 통신이 가능하도록 연결해 주는 소프트웨어 접점(통신 창구)
        - 네트워크 프로그램은 소켓을 통해 데이터를 읽거나 쓰는 스트림 입출력 작업을 통해 통신을 수행함
    - Socket 클래스
        - 클라이언트와 서버 간의 1대1 양방향 통신을 처리하는 객체
        - 소켓에 연동된 바이트 입출력 스트림을 통해 원격자 간의 실제 데이터를 직접 읽고 쓰는(송수신) 역할
        - 생성자
            - `Socket(String host, int port)`: 지정한 호스트 주소(IP, 도메인)와 포트 번호로 서버에 즉시 연결을 시도하는 클라이언트 소켓을 생성
        - 메소드
            - `InputStream getInputStream()`: 소켓을 통해 상대방이 전송한 원격 데이터를 수신(읽기)하는 InputStream을 반환
            - `OutputStream getOutputStream()`: 소켓을 통해 상대방에게 데이터를 전송(쓰기)하는 OutputStream을 반환
            - `void close()`: 소켓의 양방향 입출력 스트림을 차단하고 연결을 즉시 끊음
            - `boolean isClosed()`: 현재 소켓이 닫혀 있는지 여부를 확인하여 상태를 반환

        ```java
        try (Socket socket = new Socket("localhost", 50000);
             InputStream in = socket.getInputStream();
             OutputStream out = socket.getOutputStream()) {
        
          PrintWriter writer = new java.io.PrintWriter(out, true); // autoFlush: true
          writer.println("안녕하세요. 클라이언트입니다.");
        
        } catch (IOException e) {
          System.err.println("통신 중 에러 발생: " + e.getMessage());
        }
        ```

    - ServerSocket 클래스
        - 지정한 포트 번호를 할당받아 외부 클라이언트의 연결 요청이 들어올 때까지 기다리고, 연결 요청이 오면 실제 통신을 담당할 소켓(Socket) 객체를 생성하여 전달해 주는 역할
        - 생성자
            - `ServerSocket(int port)`: 지정된 포트 번호를 할당받아 연결 대기용 서버 소켓을 생성
        - 메소드
            - `Socket accept()`: 클라이언트의 연결 요청을 수락하고 실제 양방향 통신을 처리할 Socket 객체를 반환함 (연결 요청이 올 때까지 스레드를 블로킹 대기시킴)
            - `void close()`: 서버 소켓을 닫고 할당된 네트워크 포트 리소스를 OS에 반환함

        ```java
        try (ServerSocket server = new ServerSocket(50000)) {
          Socket client = server.accept(); // 클라이언트 접속 시까지 블로킹 대기
        } catch (IOException e) {
          System.err.println("서버 에러: " + e.getMessage());
        }
        ```
