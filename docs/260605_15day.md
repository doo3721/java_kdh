## 2~6교시: 상속, 메소드 오버라이딩, super

- 기존에 정의되어 있는 클래스의 모든 필드와 메소드를 새로운 클래스가 물려받아 사용하는 것
- 상속을 해주는 기존 클래스를 부모 클래스(상위 클래스, Super Class), 상속을 받는 새로운 클래스를 자식 클래스(하위 클래스, Sub Class)라고 함
- 상속의 특징과 장점
    - 코드의 재사용성 향상
        - 이미 검증된 부모 클래스의 코드를 재사용
        - 중복 코드가 줄어들고 개발 시간이 단축
    - 유지보수성 향상
        - 부모 클래스의 수정만으로 이를 상속받는 모든 자식 클래스에 변경 사항이 반영
        - 일관성 있는 수정 가능
    - 다형성 구현의 기반
        - 부모 클래스 타입의 참조 변수로 다양한 자식 클래스 객체를 참조
        - 확장성 높은 프로그램 설계 가능
    - 단일 상속 지원
        - Java는 다중 상속에서 발생할 수 있는 메소드 호출의 모호성(다이아몬드 문제)를 방지하기 위해 클래스의 단일 상속만을 지원함.
        - 즉, extends 뒤에는 단 하나의 클래스만 선언할 수 있다.

- 상속 선언 형식
    - 자식 클래스 선언시 extends 키워드 + 부모 클래스명을 붙여서 상속 관계를 설정
- 메소드 오버라이딩 (Method Overriding)
    - 부모 클래스로부터 상속 받은 내부 구현을 자식 클래스에서 필요에 맞게 재정의하는 기법
    - 성립 조건
        - 메소드 시그니쳐 일치: 부모 클래스의 메소드와 메소드 이름, 매개변수 타입 및 개수, 반환 타입이 동일
        - 접근 제어자 제한: 자식 클래스에서 오버라이딩하는 메소드의 접근 제어자는 부모 클래스의 메소드보다 좁은 범위로 변경할 수 없음
        - static, final, private 메소드는 오버라이딩 불가
    - 메소드 오버라이딩의 이유와 장점
        - 자식 클래스에 특화된 동작 구현: 부모 클래스의 일반적인 기능을 자식 클래스만의 구체적인 특성에 맞추어 재구성
        - 다형성 구현의 핵심: 부모 클래스 타입의 참조 변수를 사용하더라도 실제 인스턴스의 오버라이딩된 메소드가 자동으로 호출되므로 다형성을 실현
        - 코드의 유지보수성과 확장성 향상: 부모 클래스의 틀 안에서 자식 클래스들이 서로 다른 구현을 갖게 하므로, 기존 코드를 수정하지 않고도 새로운 기능을 쉽게 확장
- 오버라이딩(Overriding) vs 오버로딩(Overloading)

| **구분** | **메서드 오버라이딩 (Overriding)** | **메서드 오버로딩 (Overloading)** |
| --- | --- | --- |
| 정의 | 상속받은 부모의 메서드를 자식 클래스에서 재정의 | 한 클래스 내에서 같은 이름의 메서드를 다중 정의 |
| 메서드 이름 | 부모 메서드와 동일함 | 동일함 |
| 매개변수 | 동일함 (개수, 타입, 순서) | 달라야 함 (개수 또는 타입, 순서) |
| 반환 타입 | 동일해야 함 | 상관없음 |
| 접근 제어자 | 부모보다 좁아질 수 없음 | 상관없음 |

- super와 super()
    - 상속 관계에서 자식 객체 내부에는 부모 객체의 필드와 메소드가 포함, 이를 구분하고 생성자 흐름을 제어하기 위해 참조 키워드를 사용.
    - super
        - 자식 클래스에서 부모 클래스의 필드나 메소드에 접근할 때 사용하는 참조 변수
        - 멤버 변수 가려짐(Shadowing) 해결
            - 자식 클래스에서 부모 클래스와 동일한 이름의 필드를 선언했을 때, 자식 클래스 내부에서 이름만으로 접근하면 자식 필드가 우선
            - 부모 필드에 접근하기 위해 ‘super.필드명’을 명시
    - super() 생성자
        - 부모 클래스의 생성자 메소드
        - 자식 객체 생성시 생성자 호출 순서
            - 부모 클래스 생성자 실행 및 초기화 → 자식 생성자의 코드 실행 및 초기화
        - 첫 줄 배치 제약
            - super()는 자식 클래스 생성자 코드의 첫 번째 줄에만 위치
            - 생략할 경우 컴파일러가 생성자 첫 줄에 자동으로 super()를 주입
        - 부모 클래스의 기본 생성자가 없는 경우의 제약
            - 부모 클래스에 매개변수가 있는 생성자만 존재하고 기본 생성자가 정의되어 있지 않다면, 컴파일러는 부모 클래스의 기본 생성자를 자동 삽입하므로 에러
            - 자식 생성자에서 직접 부모 클래스의 매개변수 생성자를 호출하도록 명시해야 함.
