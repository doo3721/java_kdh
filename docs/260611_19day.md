## 1~3교시: 데이터베이스 개념, DBMS, RDBMS

- 데이터 저장의 필요성
    - 프로그램 실행 중 변수나 임시 객체에 저장된 데이터는 메모리의 휘발성 성질로 인해 프로그램이 종료되거나 전원이 꺼지면 모두 소멸됨
    - 사용자 정보, 게시글, 거래 내역 등 지속적으로 유지되어야 하는 데이터는 반드시 보조기억장치(HDD, SSD 등)와 같은 비휘발성 저장 매체에 기록하여 보존이 필요
    - 데이터 저장 기술은 메모리 기반의 임시 저장 단계에서 파일 시스템을 활용한 영구 저장 단계를 거쳐, 이를 체계적으로 제어하고 관리하는 데이터베이스 관리 시스템(DBMS) 형태로 발전됨
- 파일 시스템 방식의 한계
    - 데이터가 개별 파일 단위로 관리되어 동일한 데이터가 여러 파일에 중복 저장되는 **데이터 중복성**이 발생
    - 한 파일의 데이터를 수정했을 때 다른 파일에 반영되지 않아 데이터의 일관성이 깨지는 **데이터 불일치** 문제가 발생
    - 여러 사용자가 **동시에 동일한 파일에 접근**하여 수정할 때 충돌 제어가 어려움
    - 파일 구조가 변경되면 이를 사용하는 애플리케이션 코드도 함께 변경되어야 하는 **데이터 종속성**이 존재
- 데이터베이스
    - 특정 조직의 공동 업무 목적을 위해 다수의 사용자와 응용 프로그램이 공유할 수 있도록 통합 및 저장한 데이터의 집합
    - 데이터베이스의 4대 필수 요건
        - 통합 데이터 (Integrated Data)
            - 똑같은 데이터가 여로 곳에 흩어져 중복 저장되는 것을 방지하기 위해, 한곳에 모아서 합쳐놓은 상태
        - 저장 데이터 (Stored Data)
            - 종이 문서가 아니라 컴퓨터가 읽고 쓸 수 있는 하드디스크나 SSD 같은 디지털 저장 매체에 보관된 데이터
        - 운영 데이터 (Operational Data)
            - 임시로 보관하는 참고용 자료가 아니라, 조직이나 기업이 고유한 핵심 업무를 처리하는 데 반드시 필요한 데이터
        - 공용 데이터 (Shared Data)
            - 특정인이나 하나의 프로그램이 독점하는 것이 아니라, 여러 사용자나 업무 시스템들이 다 함께 공유하며 사용할 수 있는 데이터
    - 데이터베이스의 4대 특징
        - 실시간 접근성 (Real-Time Accessibility)
            - 사용자가 데이터를 조회했을 때, 오랜 대기 시간 없이 즉각적으로 빠른 결과를 받아볼 수 있어야 함
        - 계속적인 변화 (Continuous Evolution)
            - 새로운 정보가 생기면 추가하고, 틀린 내용은 수정하고, 불필요한 데이터는 삭제하면서 항상 최신의 올바른 정보를 유지함
        - 동시 공용 (Concurrent Sharing)
            - 여러 사용자가 같은 시점에 접속하여 동일한 데이터를 조회하거나 사용하더라도 서로 충돌 없이 안전하게 이용 할 수 있음
        - 내용에 의한 참조 (Content Reference)
            - 데이터가 디스크의 어느 주소나 물리적 위치에 보관되어 있는지 몰라도, 찾고자 하는 데이터의 값을 기준으로 직접 검색할 수 있음
- DBMS (Database Management System, 데이터베이스 관리 시스템)
    - 데이터베이스를 직접 관리하고 사용자의 요구에 따라 데이터를 조회, 삽입, 수정, 삭제하는 프로그램
    - 응용 프로그램과 물리적인 데이터 저장소(데이터베이스) 사이에서 중재자 역할
        - 사용자가 물리적인 데이터 파일에 직접 접근하여 수정하면 데이터가 손상될 위험이 크므로, 모든 데이터 접근은 DBMS 소프트ㅞ어가 중간에서 대행하고 안전하게 통제
    - 데이터 무결성 유지, 보안 제어, 동시성 제어, 장애 복구 등의 핵심 기능을 제공
- 주요 데이터베이스 유형
    - 관계형 데이터베이스(RDBMS)
        - 특징
            - 데이터를 가로(행)와 세로(열)로 구성된 2차원 테이블에 맞추어 정형화하여 관리
            - 사전에 컬럼 이름과 데이터 타입을 규정하는 스키마(Schema)를 엄격히 정의해야 함
        - 장점
            - 데이터의 무결성과 일관성이 최우선으로 보장됨
            - 여러 테이블이 join하여 복잡한 데이터를 모순 없이 다루기에 적합
        - 단점
            - 데이터 저장 구조를 도중에 바꾸기 어렵고, 대용향의 트래픽을 처리하기 위해 시스템을 여러 대로 확장(수평 확장)하는 비용이 큼
        - 적합한 서비스
            - 금융 시스템, 회원 정보 관리, 주문 및 결제 시스템 등 데이터 정합성과 신뢰성이 중요한 서비스
        - 대표 프로그램
            - MySQL, Oracle Database, PostgreSQL, Microsoft SQL Server
    - 비관계형 데이터베이스(NoSQL)
        - 특징
            - 정해진 스키마에 얽매이지 않고 자유로운 형태로 데이터를 보관
        - 장점
            - 고정된 구조가 없어 데이터가 시시각각 변해도 쉽게 추가
            - 서버를 분산하여 대규모 트래픽과 데이터를 빠르게 처리하는 데 적합
        - 단점
            - 여러 데이터를 join하는 연산이 매우 제한적이거나 무거움
            - 데이터의 일관성과 정합성 보장이 상대적으로 약하여 높은 신뢰성과 엄격한 트랜잭션 관리가 요구되는 핵심 데이터 관리에는 부적합
        - 적합한 서비스
            - 실시간 메신저(채팅), 로그 수집 시스템, 소셜 미디어 피드 등 비정형 데이터를 대량으로 신속하게 처리해야 하는 서비스
        - 대표 프로그램
            - MongoDB, Redis, Cassandra, Neo4j
    - NewSQL 및 특수 목적 데이터베이스
        - NewSQL
            - 관계형 데이터베이스의 장점(ACID 트랜잭션 보장, SQL 지원)과 NoSQL의 장점(대량 데이터에 대한 유연한 수평 확장)을 결합한 차세대 데이터베이스
            - 대표 프로그램: Google Spanner, CockroachDB)
        - 특수 목적 데이터베이스
            - 벡터 데이터베이스 (Vector DB): 생성형 AI(LLM)와 유사도 검색에 특화되어 대용량 고차원 벡터 데이터를 다룸 (Pinecone, Milvus)
            - 시계열 데이터베이스 (TSDB): 서버 모니터링 로그, 센서 데이터처럼 시간 흐름에 따라 순차적으로 발생하는 대량의 정보를 효율적으로 기록하고 분석 (InfluxDB, Prometheus)
- 관계형 데이터베이스(RDBMS)의 개념 및 구조
    - 데이터베이스 (Database)
        - RDBMS 내에서 연관된 테이블들을 하나로 묶어 관리하는 논리적 보관 공간 (스키마)
        - 예: 회원 테이블, 게시글 테이블, 댓글 테이블들을 하나의 데이터베이스인 board_db에 모아서 관리
    - 테이블 (Table)
        - 행과 열로 구성된 2차원 표 구조로 데이터를 저장하는 가장 기본적인 객체
        - 게시판: 회원 테이블, 게시글 테이블, 댓글 테이블 등
        - 쇼핑몰: 회원 테이블, 상품 테이블, 댓글 테이블 등
    - 열 (Column)
        - 테이블에서 세로 방향의 한 칸을 의미
        - 저장되는 데이터의 구체적인 종류와 타입을 규정
        - 예: 아이디, 이메일, 이름, 전화번호, 주소, 가입일
    - 행 (Row, Record)
        - 테이블에서 가로 방향의 한 줄을 의미
        - 데이터베이스에 저장되는 하나의 데이터 단위
        - 예: (아이디: 1, 이메일: haru@gmail.com, 이름: 하루, 전화번호: null, 주소: 경기도 김포시, 가입일: 2026-06-11)
    - 스키마 (Schema)
        - 테이블의 구조와 데이터 타입, 테이블 간의 제약 조건에 대한 명세를 정의
        - 회원 테이블의 스키마 예시: 테이블 이름은 member이고, 아이디 컬럼은 중복과 빈 값을 허용하지 않으며 이메일 컬럼은 문자열이며 필수여야 한다
    - 기본 키 (Primary Key, PK)
        - 테이블에서 각 행을 식별할 수 있는 유일한 값을 가지는 키
        - 기본 키는 null값을 가질 수 없으며 중복된 값을 가져서도 안 됨
    - 외래 키 (Foreign Key, FK)
        - 다른 테이블의 기본 키를 참조하여 테이블 간의 유기적인 관계를 형성하는 칼럼
        - 참조 무결성 규칙에 따라 외래 키의 값은 참조 대상 테이블의 기본 키 값 중 하나이거나 null이어야 함
    - 테이블 간의 관계
        - 1:N 관계
            - 한쪽 테이블의 레코드 1개가 다른 쪽 테이블의 레코드 여러 개와 연결될 수 있는 가장 일반적인 관계
            - N에 해당하는 테이블에 외래 키(FK)를 배치하여 1에 해당하는 테이블의 기본 키(PK)를 참조하도록 설계함
            - 예: 하나의 회원(1)이 여러 개의 게시글을 작성(N)
        - N:M 관계
            - 양쪽 테이블의 레코드가 서로의 레코드 여러 개와 연결될 수 있는 관계
            - RDBMS에서는 다대다 관계를 직접 테이블로 생성할 수 없으므로, 두 테이블의 기본 키를 외래 키로 가지는 매핑 테이블(연결 테이블)을 중간에 두어 1:N 및 M:1 관계로 해소하여 설계함
            - 예: 한 명의 학생(N)이 여러개의 과목(M)을 수강하고, 하나의 과목(M)을 여러 명의 학생(N)이 수강하는 관계

## 4~6교시: SQL, 테이블 생성

- SQL (Structured Query Language)
    - 관계형 데이터베이스의 데이터를 정의, 조작, 제어하기 위해 고안된 표준 컴퓨터 언어
    - 사용자가 데이터가 저장된 물리적 위치나 처리 방식의 세부 과정을 지시하지 않고, 원하는 결과만 명시하여 명령을 수행하는 비절차적 언어의 성격을 가짐
    - DBMS에 직접 명령을 전달하여 테이블 스키마를 설계하거나, 레코드를 검색, 추자, 갱신, 삭제할 수 있으며 복잡한 제어 및 트랜잭션 관리도 통합 수행
    - 주요 기능별 분류
        - DDL (Data Definition Language, 데이터 정의어)
            - 테이블이나 뷰 등 데이터베이스 객체의 구조를 생성, 변경, 삭제하기 위해 사용하며 CREATE, ALTER, DROP 등의 명령어가 포함됨
        - DML (Data Manipulation Language, 데이터 조작어)
            - 테이블 내부의 데이터를 다루기 위해 사용하며 INSERT, SELECT, UPDATE, DELETE 등의 명령어가 포함됨
        - DCL (Data Control Language, 데이터 제어어)
            - 데이터베이스 보안 및 접근 통제를 위해 권한을 관리하며, GRANT, REVOKE 등의 명령어가 포함됨
- DDL (Data Definition Language)
    - 데이터베이스의 물리적인 구조를 생성, 변경, 삭제하는 명령어 집합
    - 관계형 데이터베이스의 뼈대가 되는 테이블을 DDL을 사용하여 정의
- 데이터 생성, 전환 및 삭제
    - 데이터베이스 서버 내에 새로운 스키마를 생성하고 사용을 위해 전환하거나 필요없는 데이터베이스 삭제
    - 테이블을 정의하고 데이터를 적재하기 전에 선행적으로 데이터베이스 인스턴스를 마련하거나 정리하는 기초적인 단계
    - 생성: `CREATE DATABASE 데이터베이스명;`
    - 전환: `USE 데이터베이스명;`
    - 삭제: `DROP DATABASE 데이터베이스명;`
- 테이블 생성 (CREATE TABLE) 및 제약조건
    - 데이터베이스 내의 데이터를 논리적으로 구조화하여 저장할 수 있도록 물리적인 테이블 구조를 정의하고 생성
    - 컬럼의 이름, 데이터 타입 및 다양한 무결성 제약조건을 사전에 규정하여 안전한 데이터 저장 공간을 설계하는 출발

    ```sql
    CREATE TABLE 테이블명 (
      컬럼명 데이터타입 [제약조건],
      ...
      [테이블_제약조건]
    );
    ```

    - 주요 데이터 타입 종류
        - 숫자형
            - INT: 정수형 데이터 (4bytes)
            - BIGINT: 대용량 정수형 데이터 (8bytes), 대규모 식별자 등에 주로 사용
            - DECIMAL (전체자릿수, 소수자릿수): 고정 소수점 실수를 저장하며 소수점 오차가 없는 정확한 연산이 필요한 금융 데이터 등에 사용
        - 문자형
            - CHAR(길이): 고정 길이 문자열 데이터 (지장한 길이보다 짧은 값을 저장하면 공백으로 채워짐
            - VARCHAR(길이) : 가변 길이 데이터를 저장 (지정한 길이 내에서 실제 입력된 데이터의 크기만큼만 저장 공간을 사용하므로 효율적)
            - TEXT : 본문글, 댓글 내용 등 대용량 텍스트 데이터를 저장
        - 날짜/시간형
            - DATE: 연, 월, 일 날짜 정보만 저장 (YYYY-MM-DD 형식)
            - TIME: 시, 분, 초 시간 정보만 저장 (HH:MM:SS 형식)
            - DATETIME
                - 타임존의 영향을 받지 않고 입력된 고정 시간값을 보전 (5바이트 저장 공간 사용)
                - 2038년 표현 한계가 없고 타임존 설정 불일치로 인한 오차를 방지할 수 있어 현대 백엔드 개발 시 관장
            - TIMESTAMP: 시스템의 타임존에 따라 내부적으로 UTC 시간값으로 자동 변환되어 저장 및 조회됨 (4바이트 저장 공간, 1970~2038년 지원 범위)
    - 주요 제약조건 종류
        - PRIMARY KEY (기본 키)
            - 테이블 내의 행을 고유하게 식별할 수 있는 컬럼으로 지정
            - 중복값과 빈 값(null)을 허용하지 않음
        - FOREIGN KEY (외래 키)
            - 다른 테이블의 기본 키를 참조하여 테이블 간의 연결 관계를 형성
            - 데이터 참조 무결성을 보장하기 위해 사용
            - 외래 키 참조 옵션 종류
                - ON DELETE CASCADE: 부모 테이블의 레코드가 삭제되면 자식 테이블의 레코드도 함께 자동 삭제
                - ON DELETE SET NULL: 부모 테이블의 레코드가 삭제되면 자식 테이블의 외래 키 값을 NULL로 변경
                - ON DELETE RESIRICT: 자식 테이블이 참조하고 있는 부모 테이블의 레코드는 삭제가 불가능하도록 차단
        - 외래 키 지정 방법
            - 컬럼 레벨 정의
                - 컬럼 옆에 REFERNCES 부모테이블(부모컬럼) 형태로 직접 정의
                - MySQL(InnoDB) 환경에서는 문법 에러 없이 통과되나 실제 외래 키 제약조건이 작동하지 않고 무시되는 한계가 존재

                ```sql
                user_id INT REFERENCES member(id)
                ```

            - 테이블 레벨 정의
                - 테이블 생성 쿼리 하단에 FOREIGN KEY (자식컬럼) REFERENCES 부모테이블(부모컬럼) 형태로 명시하여 정의하는 방식
                - 안정적인 무결성 보장을 위해 권장하는 방식

                ```sql
                FOREIGN KEY (user_id) REFERENCES member(id)
                ```

            - 테이블 생성 후 추가 정의
                - 테이블을 이미 생성한 이후 ALTER TABLE 명령어를 통해 외래 키 제약조건을 추가하는 방식

                ```sql
                ALTER TABLE post ADD CONSTRAINT fk_post_member FOREIGN KEY (user_id) REFERENCES member(id);
                ```

        - NOT NULL: 해당 컬럼에 반드시 값이 존재하도록 규정
        - UNIQUE: 컬럼 내의 모든 데이터 값이 서로 중복되지 않ㄷ고 유일하도록 보장
        - DEFAULT
            - 데이터를 저장할 때 값을 명시하지 않으면 자동으로 입력될 기본값을 설정
            - 기본값으로 사용할 수 있는 주요 유형
                - 리터럴 상수
                - NULL
                - 내장 함수
        - AUTO_INCREMENT: 새로운 행이 추가될 때마다 정수형 식별자 값을 자동으로 1씩 증가하여 부여
