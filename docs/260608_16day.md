## 3~5교시: final, Object 클래스

- final
    - 대상에 따라 변경 불가능하도록 최종적인 상태로 확정하는 제약을 부여
    - 변수: 변수 선언시 붙으면 상수가 되어 한 번 결정된 값을 수정할 수 없음
    - 메소드: 메소드 선언시 붙으면 자식 클래스에서 해당 메소드를 오버라이딩하여 재정의 할 수 없음
    - 클래스
        - 클래스 선언시 붙으면 더 이상 상속의 부모 클래스가 될 수 없음
        - 자식 클래스를 생성 할 수 없도록 클래스 계층 구조를 제한함
- Object 클래스
    - 자바에서 생성되는 모든 클래스는 별도의 extends 선언이 없더라도 기본적으로 java.lang.Object 클래스를 최상위 부모로 상속 받음
    - 상속 계층의 최상위: 어떤 클래스든 결국 Object 클래스의 자식이 되므로, 자바의 모든 객체는 Object 타입으로 선언이 가능함
    - 공통 기능 제공: Object 클래스는 모든 객체가 기본적으로 가져야 할 공통 메소드를 제공
- Object의 주요 메소드
    - toString()
        - 객체의 문자열 정보를 반환하는 메소드
        - 기본 구현은 클래스명과 해시코드 출력
        - 멤버 필드 값을 출력하도록 재정의하여 디버깅에 활용
    - equals(Object obj)
        - 두 객체의 동등성을 비요하는 메소드
        - 기본 구현은 주소값 비교(==)
        - 논리적 내용 비교가 필요한 경우 재정의
    - hashCode()
        - 객체의 고유한 정수 해시코드를 반환하는 메소드
        - equals 메소드를 재정의할 때 동등한 객체는 동일한 해시코드를 반환해야 한다는 규약에 따라 함께 재정의하는 것이 관례

> [!NOTE]
> 해시 (Hash)
> - 임의의 크기를 가진 데이터를 고정된 크기의 고유한 값으로 변환하는 기술 
> - 입력값이 같으면 항상 동일한 해시값을 반환 
> - 출력된 해시값을 통해 역으로 원래 데이터를 유추할 수 없는 단방향성을 가짐 
> - HashMap이나 HashSet 같은 해시 기반 자료구조에서는 객체의 해시값을 내부 저장소의 index로 활용하여 데이터 추가, 삭제, 검색 성능을 획기적으로 향상시킴


## 6교시: 포함/상속 관계, 다형성

- 포함 관계 (Has-A)
    - 한 클래스가 다른 클래스의 인스턴스를 자신의 필드로 선언하여 소유하는 관계
    - “~은 ~을 가지고 있다”(Has-A)로 자연스럽게 설명될 때 포함 관계를 선택
- 상속 관계 (Is-A)
    - 부모 클래스의 특성을 그대로 물려받아 자식 클래스로 구체화하여 설계하는 관계
    - “~은 ~이다”(Is-A)로 자연스럽게 설명될 때 상속 관계를 선택
- 올바른 설계 선택 방향
    - 상속의 오남용 방지
        - 상속은 강력한 재사용 도구이지만, 부모와 자식 간의 결합도가 매우 높아져 부모의 변경이 자식에게 큰 영향을 미침
        - 단순히 코드를 재사용하기 위해 억지로 상속 관계를 맺으면 설계 왜곡 가능성 존재
        - Has-A 관계 우선 고려: 두 클래스의 관계가 순수한 Is-A 구조가 아니라면, 대부분 포함 관계(Has-A) 관계를 사용하는 것이 설계의 유연성을 확보하고 결합도 낮춤
- 다형성
    - 하나의 타입(부모 클래스나 인터페이스)으로 여러 가지 객체(자식 객체)를 참조하고 제어할 수 있는 객체지향의 핵심 특징
    - 동일한 호출(메소드 호출)을 하더라도 참조하는 실제 인스턴스에 따라 서로 다른 결과와 동작을 나타내는 성질을 의미함
    - 다형성 성립의 3대 조건
        - 상속 관계: 클래스 간 상속이나 인터페이스 구현 구조가 선언되어 있어야함
        - 메소드 오버라이딩: 자식 클래스가 부모 클래스의 메소드를 재정의하여 자신의 기능으로 변경
        - 부모 타입의 참조 변수 사용: 부모 클래스나 인터페이스 타입의 변수로 자식 객에를 가리켜 제어해야 함 (업캐스팅)
- 업캐스팅과 다운캐스팅
    - 업캐스팅: 자식 객체를 부모 타입으로 형변환하는 것 (자동 형변환)
    - 다운캐스팅: 부모 타입으로 형변화된 객체를 다시 원래의 자식 타입으로 형변환하는 것 (명시적 형변환)
        - 주의: 실제 생성된 인스턴스 타입과 일치하지 않는 다른 자식 타입으로 잘못 다운캐스팅할 경우 ClassCastException이 런타임에 발생
- instanceof 연산자
    - 참조 변수가 실제로 어떤 타입의 객체를 가리키고 있는지 확인할 때 사용
    - if 등으로 확인하여 블록에서 해당 자식 클래스의 메소드를 불러올 때 유용
