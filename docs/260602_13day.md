## 2~5교시: 객체 생성, 생성자, this 키워드

- 객체의 생성과 사용 방법
  - 인스턴스(객체)를 생성하려면 new 연산자 사용
  - 객체의 멤버(필드,메소드)에 접근하기 위해서는 닷(.) 연산자를 사용
- new 연산자를 통한 인스턴스화 과정
  - new 연산자는 JVM에게 객체를 저장할 공간을 힙 영역에 할당하도록 요청
  - 메모리 할당이 완료되면 클래스에 정의된 필드들이 힙 영역에 생성, 생성자를 호출해 초기화를 마침.
  - 생성된 객체가 위치한 힙 영역의 참조 주소값(Reference)을 반환하여 변수에 대입할 수 있게 함
- 생성자 (Constructor)
  - 객체가 new 연산자를 통해 메모리에 생성될 때, 가장 먼저 호출되어 인스턴스 변수의 초기화를 담당하는 특수 메소드
  - 특징
    - 반환 타입이 없음
    - 기본 생성자 (Defalut Constructor)
      - 클래스 내부에 개발자가 단 하나도 생성자를 선언하지 않을 때 기본적으로 생성
      - 컴파일러가 매개변수와 코드가 없는 빈 기본 생성자를 생성
      - 단, 매개변수가 있는 생성자를 하나라도 정의하면, 기본 생성자는 자동으로 생성되지 않음. 따라서 필요시 직접 명시.
- 생성자 오버로딩
  - 매개변수의 개수와 타입을 다르게 하여 하나의 클래스 내부에 생성자를 여러 개 조립하여 다형성을 제공할 수 있음
- this와 this()
  - this
    - 생성된 자기 자신 객체를 가리키는 참조 변수
    - 매개변수와 필드명이 같을 때 구별하기 위해 사용
  - this()
    - 같은 클래스 내의 다른 생성자를 호출 할 때 사용
    - 생성자 내부의 첫 줄에만 작성 가능

## 6교시: 패키지, 캡슐화

- 패키지
  - 관련된 클래스들을 그룹화하는 폴더 구조
  - 임포트 (import)
    - 다른 패키지에 있는 클래스를 사용할 때 명시
    - 단, java.lang 패키지에 속한 클래스(String, System 등)는 import 없이 자동으로 사용 가능
- 캡슐화
  - 중요한 데이터와 이를 처리하는 메소드를 하나로 묶고, 외부에서 임의로 변경하지 못하도록 데이터를 은닉하는 기법
  - 접근 제어자: private < defalut < protected < public 순으로 접근 권한을 제한 (오른쪽일수록 범위가 넓음)
  - 필드는 private로 선언, Getter/Setter 및 유효성 검증 메소드를 통해서만 접근하도록 제한
- 접근 제어자별 세부 접근 범위
  - public: 어떠한 제한 없이 모든 곳에서 접근 가능
  - protected: 동일한 패키지 내의 클래스 및 다른 패키지의 상속받은 자식 클래스
  - defalut (package-private): 제어자가 생략했을 때 자동으로 부여, 동일 패키지 내부에서만 접근 가능
  - private: 오직 선언된 해당 클래스 내부에서만 접근 가능

| 접근 제어자 | 클래스 내부 | 동일 패키지 | 동일 패키지 또는 자식 클래스 | 어디서나 |
| :--- | :--- | :--- | :--- | :--- |
| public | 허용 (O) | 허용 (O) | 허용 (O) | 허용 (O) |
| protected | 허용 (O) | 허용 (O) | 허용 (O) | 차단 (X) |
| default | 허용 (O) | 허용 (O) | 차단 (X) | 차단 (X) |
| private | 허용 (O) | 차단 (X) | 차단 (X) | 차단 (X) |
