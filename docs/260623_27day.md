## 1교시: 복습

## 2교시: Collection 인터페이스, List 인터페이스

- Collection 인터페이스
    - List, Set, Queue 인터페이스의 공통 부모 인터페이스
    - 데이터를 그룹으로 묶어 관리하는 기본적인 공통 메소드들을 정의함
    - 주요 메소드
        - `boolean add(E e)`: 컬렉션에 요소를 추가함
        - `boolean remove(Object o)`: 컬렉션에서 지정된 요소를 삭제함
        - `int size()`: 컬렉션에 포함된 요소의 개수를 반환함
        - `boolean isEmpty()`: 컬렉션이 비어있는지 여부를 판단함
        - `boolean contains(Object o)`: 컬렉션에 지정된 요소가 포함되어 있는지 확인함
        - `void clear()`: 컬렉션의 모든 요소를 삭제함
        - `Iterator<E> iterator()`: 컬렉션의 요소를 순회하기 위한 Iterator를 반환함
- List 인터페이스
    - 순서를 유지하여 데이터의 중복 저장을 허용
    - 주요 메소드
        - `E get(int index)`: 지정된 인덱스 위치의 요소를 반환함
        - `E set(int index, E element)`: 지정된 인덱스의 요소를 새로운 객체로 대체함
        - `void add(int index, E element)`: 지정된 인덱스 위치에 요소를 삽입함
        - `E remove(int index)`: 지정된 인덱스 위치의 요소를 삭제함
        - `int indexOf(Object o)`: 지정된 객체가 위치한 인덱스를 탐색하여 반환함
    - ArrayList
        - 내부적으로 크기 조절이 가능한 배열 구조를 사용
        - 장점: index를 통한 데이터 조회 속도가 매우 빠름
        - 단점: 리스트 크기 확장 시 배열 복사가 일어나고, 중간에 데이터를 삽입/삭제할 때 기존 데이터들을 뒤로 밀어내거나 앞으로 당기는 이동 연산이 추가되어 성능이 저하됨
    - LinkedList
        - 이중 연결 리스트 노드 구조로 각 노드가 이전 노드와 다음 노드의 참조 주소를 보유
        - 장점: 중간에 데이터를 삽입하거나 제거할 때 링크 연결 정보만 변경하므로 배열 복사와 같은 연산이 일어나지 않음
        - 단점: 특정 인덱스의 요소를 찾기 위해 처음 또는 끝부터 링크를 타고 순차적으로 조회해야 하므로 검색 성능이 저하

  | **항목** | **ArrayList** | **LinkedList** |
      | --- | --- | --- |
  | 내부 구조 | 가변 배열 | 이중 연결 리스트 |
  | 인덱스 조회 | 빠름 | 느림 |
  | 첫 위치 삽입/삭제 | 느림 | 빠름 |
  | 마지막 위치 삽입/삭제 | 빠름 | 빠름 |
  | 중간 삽입/삭제 | 느림 | 느림 |
  | 메모리 사용량 | 적음 (데이터만 저장) | 많음 (참조 주소 보관용 메모리 추가 필요) |

## 3~4교시: Set, Map

- Set 인터페이스
    - 데이터의 저장 순서를 보장하지 않으며 중복 저장 불가
    - 주요 메소드
        - `boolean add(E e)`: 중복이 없는 경우에만 요소를 추가함 (추가 성공 시 true, 이미 존재 시 false 반환)
        - `boolean remove(Object o)`: 지정된 객체를 삭제함
        - `boolean contains(Object o)`: 지정된 객체가 포함되어 있는지 여부를 확인함
        - `Iterator<E> iterator()`: 컬렉션의 요소를 순회하기 위한 Iterator를 반환함
    - HashSet
        - 해시 테이블 구조를 사용하여 데이터를 보관
        - 장점: 요소의 추가, 삭제, 검색 성능이 데이터 양에 관계없이 일정하고 신속
    - TreeSet
        - 이진 탐색 트리 (Red-Black Tree) 구조를 기반으로 설계
        - 장점: 추가하는 데이터가 자동으로 오름차순 정렬되어 보관
        - 단점: 데이터가 들어올 때마다 트리 구조 재조정이 일어나므로 HashSet에 비해 삽입/삭제 성능이 느림

  | **항목** | **HashSet** | **TreeSet** |
      | --- | --- | --- |
  | 내부 자료구조 | 해시 테이블 | 이진 탐색 트리 (Red-Black Tree) |
  | 정렬 특징 | 순서 없음 (정렬 없음) | 정렬 있음 (기본 오름차순) |
  | 성능 | 상대적으로 매우 빠름 | 정렬을 동반하므로 상대적으로 느린 편 |
- Map 인터페이스
    - Key와 Value가 한 쌍(Entry)을 이루는 방식으로 데이터를 저장하여 Key는 중복 불가, Value는 중복 허용
    - 주요 메소드
        - `V put(K key, V value)`: 지정된 키와 값을 추가함 (동일한 키가 존재하면 기존 값을 덮어씀)
        - `V get(Object key)`: 지정된 키에 대응하는 값을 반환하며, 존재하지 않으면 null을 반환함
        - `V remove(Object key)`: 지정된 키와 그에 대응하는 값을 함께 삭제함
        - `Set<K> keySet()`: 모든 키 정보를 Set 형태로 반환함
        - `Set<Map.Entry<K, V>> entrySet()`: 모든 Key-Value 쌍(Map.Entry)을 Set 형태로 반환함
    - HashMap
        - 해시 함수를 통해 Key의 저장 위치를 결정하므로 정렬 순서가 보장되지 않음
        - 장점: 추가, 삭제, 검색 속도가 매우 빠름
    - TreeMap
        - 이진 탐색 트리 (Red-Black Tree) 기반으로 동작하여 Key 값을 기준으로 자동 오름차순 정렬 상태를 유지
        - 장점: 범위 검색이나 정렬된 리스트를 반환할 때 적합
        - 단점: 요소를 추가할 때 정렬 연산이 동반되어 HashMap 대비 성능에 차이 존재
    - Map의 데이터 탐색 기법
        - keySet()
            - 전체 Key 정보를 Set 형태로 반환받아 순회함
            - 순회 루프 안에서 Value를 꺼내기 위해 get() 메소드를 반복 호출하므로 비효율적
        - entrySet()
            - Key와 Value가 결합된 Entry 정보를 Set 형태로 가져와 순회
            - 추가적인 조회 없이 Key와 Value를 한 번에 볼 수 있어 대량 데이터를 순회할 때 권장

  | **항목** | **HashMap** | **TreeMap** |
      | --- | --- | --- |
  | 내부 자료구조 | 해시 테이블 | 이진 탐색 트리 (Red-Black Tree) |
  | 정렬 기준 | 순서 보장 없음 | Key 기준 자동 오름차순 정렬 |
  | Null 허용 | Key 및 Value 모두 Null 지정 허용 | Key로 Null 지정 불가 |

## 5~6교시: 제네릭

- 제네릭 (Generic)
    - 제네릭 이전의 한계 (JDK 1.5 미만)
        - 제네릭이 없던 시절에는 다양한 타입의 객체를 저장하기 위해 모든 클래스의 최상위 부모인 Object 타입을 활용함
        - 이 방식은 객체를 컬렉션에 임시 보관한 뒤 다시 꺼내서 쓸 때, 매번 명시적인 캐스팅(강제 타입 변환) 처리를 거쳐야 했음
        - 코드가 지저분해질 뿐만 아니라, 개발자가 실수로 엉뚱한 타입으로 변환하려고 시도할 경우 컴파일 시점에는 에러가 발견되지 않고 실행 도중(Runtime)에 ClassCastException을 일으켜 프로그램이 종료되는 치명적인 결함이 존재했음
    - 제네릭 도입에 따른 이점
        - 타입 안정성 확보: 클래스나 메소드 내부에서 다룰 데이터 타입을 선언 시점이 아닌 객체 생성 시점(인스턴스화)에 정하도록 하여, 엉뚱한 객체가 보관되는 일을 컴파일 수준에서 완벽하게 필터링함
        - 타입 캐스팅 생략: 데이터를 꺼낼 때 컴파일러가 대입된 타입에 맞게 자동 타입 변환을 지원하므로 불필요하고 번거로운 캐스팅 코드가 생략되어 코드가 한결 간결해짐
- 제네릭 기본 사용법
    - 제네릭 클래스 선언과 객체 생성
        - 클래스 이름 옆에 다이아몬드 기호 <T>를 붙여 해당 클래스가 제네릭 타입 파라미터 T를 사용함을 명시함
        - 인스턴스화 할 때 생성자 뒤의 다이아몬드 연산자 내 타입은 생략 가능함 (컴파일러의 타입 추론 지원)
    - 타입 파라미터 이름 약속 기호
        - 관례적으로 의미를 유추하기 쉬운 단일 대문자 영문을 약속 기호로 사용함
        - T: Type (가장 범용적인 타입을 지칭)
        - E: Element (컬렉션에 보관할 요소를 타겟으로 지정할 때 사용)
        - K: Key (Map 구조 등에서 식별자 키 타입을 지칭)
        - V: Value (Map 구조 등에서 식별 데이터의 값 타입을 지칭)
        - N: Number (숫자 관련 타입으로 범위를 좁힐 때 사용)
- 제한된 타입 파라미터 (Bounded Type Parameter)
    - 필요성: 제네릭 타입 파라미터에 아무 타입이나 다 대입할 수 있으면, 객체 내부에서 특정 클래스의 전용 메소드(예: 숫자 연산 메소드 등)를 호출하는 안전한 비즈니스 로직 설계가 불가능함
    - 구현 방법: extends 키워드를 선언부의 타입 변수 뒤에 붙여 특정 클래스나 인터페이스를 상속받은 타입들만 주입받도록 강제 범위를 고정함
        - `<T extends Number>`: 이 경우 T에는 Number 클래스 및 그 하위 클래스(Integer, Double 등)만 대입 가능하며, 객체 내부에서 Number 클래스의 메소드(doubleValue() 등)를 안전하게 호출할 수 있음
